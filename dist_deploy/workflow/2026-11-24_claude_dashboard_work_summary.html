1작업 개요

관리자 로그인 후 모바일 화면에서 가로 폭이 넘치고 메뉴와 내용이 뒤섞이던 문제를 수정하고, 콘솔 오류를 정리한 뒤 GitHub main 브랜치로 배포했습니다.

2원인 분석

2-1. 가로 폭 넘침

CSS 그리드의 1fr 칸은 안에 든 내용보다 좁아질 수 없는 기본 동작(min-width:auto)이 있습니다. 표에 min-width:760px가 걸려 있어 칸이 화면보다 넓어졌고, 이로 인해 페이지 전체가 가로로 넘쳤습니다.

2-2. 사이드바 65px 충돌

기존 @media(max-width:768px) 블록(약 875줄)에 .sidebar{width:65px}, .main{margin-left:65px; max-width:calc(100% - 65px)}가 남아 있었습니다. 이후에 추가한 하단 탭바 규칙이 이를 덮어쓰는 구조였기 때문에, 우선순위가 어긋나면 사이드바가 좌측을 가로막을 수 있었습니다. 충돌의 근원인 옛 규칙을 직접 삭제했습니다.

2-3. 콘솔 오류 (google_ads)

구글 앱스스크립트(GAS) 응답이 {visits, quotes} 형식이 아니어도(예: 오류 객체) 그대로 analyticsData에 대입되어, 렌더링 중 visits가 없어 오류가 발생했습니다.

GAS가 형식이 맞지 않는 응답을 보내는 이유 자체는 확인하지 못했습니다. 앱스스크립트 쪽 점검이 필요합니다.

3수정 내용

  • 넘침 방지: 그리드 열을 minmax(0,1fr)로, 그리드 자식에 min-width:0, html/body에 overflow-x:hidden 적용. 넓은 표는 .table-scroll 안에서만 스크롤.
  • 하단 탭바(≤768px): position:fixed; left:0; right:0; bottom:0; width:100%. 아이콘+글자 세로 배치, 가로 스크롤, 로그아웃 항목은 모바일 탭바에만 추가.
  • 본문: margin-left:0, 폭 100%, 하단 탭바 높이만큼 아래 여백 확보.
  • 상단 영역: 세로 정렬, 바로가기 버튼은 2열 그리드.
  • 견적/로그 표: 모바일에서 카드형 목록으로 변환(회사명을 맨 위에 크게 표시).
  • 차트: 카드·컨테이너에 max-width:100%, overflow:hidden, 캔버스 폭 100%. 창 크기 변경 시 resize() 호출. (responsive:true, maintainAspectRatio:false는 기존 설정 유지)
  • 시뮬레이터: 슬라이더와 결과표를 flex-direction:column으로 세로 1열 배치, 결과표 열은 폭 안에서 줄바꿈.
  • 480px 이하: KPI 카드 1열, 빠른 메뉴 2열.
  • 오류 대응: GAS 응답에 visits/quotes가 없으면 로컬 데이터로 폴백, renderDashboardData()에 기본값 보정 코드 추가.

4검증 내용

  • headless Chrome은 창 폭을 약 504px 아래로 줄이지 못해, 처음 스크린샷은 504px 레이아웃을 362px로 잘라낸 것이었습니다(테스트 오류).
  • 362px 폭 iframe으로 다시 측정한 결과 본문 폭 347px(스크롤바 제외), 페이지 전체의 가로 넘침 없음. 넘치는 요소는 가로 스크롤되는 하단 탭 항목뿐이며 의도한 동작입니다.
  • 테스트 시 데이터가 0건이어서 차트가 비어 있었습니다. 데이터가 있는 상태의 차트 표시와 실기기 확인은 하지 못했습니다.
